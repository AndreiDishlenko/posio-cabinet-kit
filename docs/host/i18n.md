# Language of the public site

The cabinet chooses its language on the server (user setting → session →
cookie) and switches it with `_LangSelector`. The public site can use the
same mechanism, so one choice holds for both.

## Checklist

1. **Server — public routes.** Append the package middleware to the `web`
   group in `bootstrap/app.php`:

   ```php
   $middleware->web(append: [
       'cabinet-kit.locale', // applies the visitor language
       'cabinet-kit.i18n',   // shares cabinetKitI18n + serverlocale with Inertia
       HandleInertiaRequests::class,
   ]);
   ```

2. **Offered languages** come from `cabinet-kit.translations.locales` in
   `config/cabinet-kit.php` (default: `uk`, `en`).

3. **Client — the site's app setup** (the same code for the browser and SSR):

   ```js
   import cabinetKitSiteI18n from '@cabinet-kit/siteI18n.js';

   app.use(cabinetKitSiteI18n, {
       messages: { uk: siteUk },     // the site's own translations per language
       page: props.initialPage,      // first Inertia page: language chosen by the server
   });
   ```

   This installs vue-i18n as `$t`. Do not define another global `$t` on the
   site. Keys are the original English text, so English needs no dictionary.

4. **Switch.** Render the cabinet selector in its compact inline form:

   ```html
   <LangSelector mode="inline" class="my-lang-switch" />
   ```

   `import LangSelector from '@cabinet-kit/Custom/_LangSelector.vue'`. Restyle it
   through variables on your class, never by copying the component:

   | variable | default |
   |---|---|
   | `--lang-switch-color` | `inherit` |
   | `--lang-switch-bg` / `--lang-switch-border` / `--lang-switch-radius` / `--lang-switch-padding` | none / none / pill / 0 |
   | `--lang-switch-font-size` / `--lang-switch-font-weight` / `--lang-switch-letter-spacing` / `--lang-switch-line-height` | 0.875rem / 500 / normal / 1.25rem |
   | `--lang-switch-item-padding` / `--lang-switch-item-radius` | 0.125rem 0.375rem / 0.25rem |
   | `--lang-switch-idle-opacity` / `--lang-switch-hover-opacity` | 0.5 / 0.75 |
   | `--lang-switch-active-color` / `--lang-switch-active-bg` | inherit / none |

   `variant="pill"` gives the cabinet header look: a 36px pill with a shadow
   outline that flattens on hover. Its size, shape and animation are fixed; only
   colors are yours:

   | variable | default |
   |---|---|
   | `--lang-switch-bg` / `--lang-switch-color` | `--button-background` / `--button-text-color` |
   | `--lang-switch-shadow-color` / `--lang-switch-border` | stone 50% / none |
   | `--lang-switch-hover-bg` | none |
   | `--lang-switch-active-color` / `--lang-switch-active-bg` | inherit / none |

   For a switch not wired to i18n, use `@cabinet-kit/Elements/LangSwitch.vue`
   directly (`locales`, `current`, `label` props, `change` event).

Choosing a language stores it (browser + server session) and, on routes named
`<name>.<locale>`, moves to the same page in that language. Pages without
localized routes stay where they are and only switch `$t` texts.

## Localized public routes (one page per language)

When every public page must exist in each language with its own address
(`/about` and `/en/about`), register the public routes once per language and
name them `<name>.<locale>`:

```php
foreach (config('general.locales') as $locale) {
    $prefix = $locale === config('general.unprefixed_locale') ? '' : $locale;

    Route::prefix($prefix)
        ->middleware('cabinet-kit.set-locale')
        ->group(function () use ($locale) {
            Route::get('/', HomeController::class)->name("home.$locale");
            Route::get('/about', AboutController::class)->name("about.$locale");
        });
}
```

`cabinet-kit.set-locale` takes the language from the address and stores it in
the session and cookie, so routes outside the group (form posts, unsubscribe
links) answer in the same language when they use `cabinet-kit.locale`.

Build links with `loc_route('about')` on the server and `$locRoute('about',
locale, params)` in Vue. SEO (`hreflang`, `x-default`, canonical) and the
sitemap pick the localized routes up by their names.

Keys in `config/general.php`:

| key | meaning |
|---|---|
| `locales` | languages that have public pages |
| `default_locale` | language of the site when nothing else decides |
| `unprefixed_locale` | language served without a prefix (`/about`); empty — every language has a prefix and the bare address redirects |
| `site_fallback_locale` | language that fills missing translations (PHP and the site's `$t`); keep it on the language the package keys are written in (`en`) |
| `x_default_locale` | language of the `x-default` alternate link |

An address without a prefix always means `unprefixed_locale`: the visitor's
cookie or browser language never redirects it. The browser language is used
only where the address does not decide (cabinet, sign-in, registration).

### Site dictionaries keyed in the site language

By default the site's keys are English text. A site that writes its keys in
its own language (for example Ukrainian) passes `sourceLocale`:

```js
app.use(cabinetKitSiteI18n, {
    messages: { uk: siteUk, en: siteEn },
    sourceLocale: 'uk',
    page: props.initialPage,
});
```

For `sourceLocale` a key is shown as is, so the Ukrainian page never falls back
to the English dictionary; `siteEn` translates those keys. `siteUk` then holds
only translations of the package's English keys and semantic keys of long texts.
